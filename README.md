# Online_Video_LLM

Онлайн (потоковые) видео-LLM, которые отвечают **проактивно**: вопрос задаётся в начале видео, а модель должна
дождаться момента, когда ответ становится виден, ответить вовремя и обновлять ответ, если он меняется.

В репозитории: конвейеры подготовки датасетов, общий формат данных, обучение (собственный цикл на
`transformers`) и оценка.

Архитектура Qwen2.5-VL-3B + LoRA + MLP состояния, конфиг и smoke-тесты: [models/README.md](src/online_vllm/models/README.md).

## Датасеты

| датасет | что это | train / eval | описание |
|---|---|---|---|
| **CLEVRER-Proactive** | проактивные вопросы, сгенерированные по аннотациям [CLEVRER](http://clevrer.csail.mit.edu/) | 180 783 / 90 287 вопросов, 10 000 / 4 999 видео | [dataset_builders/clevrer_proactive/README.md](dataset_builders/clevrer_proactive/README.md) |

Данные в git не хранятся: сырые файлы скачиваются, готовые датасеты пересобираются скриптами.

## Структура

```
dataset_builders/<датасет>/   конвейер подготовки одного датасета: download → generate → balance → export (+ viewer)
src/online_vllm/
    data/schema.py            общий формат записи (время в секундах) — всё, что видят обучение и оценка
    data/video.py             чтение видео как потока кадров с заданной частотой
    models/  train/  eval/    модели, цикл обучения, метрики своевременности ответа
configs/                      конфиги данных, моделей и обучения
scripts/                      точки запуска (подготовка данных, обучение, оценка)
tests/                        проверки инвариантов датасетов
data/                         не в git: raw/ (исходники), cache/, processed/ (готовые датасеты)
outputs/                      не в git: чекпоинты, логи, результаты оценки
```

Каждый датасет в `dataset_builders/` на выходе даёт `data/processed/<датасет>/<split>.jsonl` в общем формате
(`src/online_vllm/data/schema.py`): видео, момент вопроса, варианты ответа и интервалы `[start, end)` с ответом,
верным на этом интервале, плюс окно допуска своевременного ответа. Поэтому обучение и оценка не зависят
от того, из какого датасета пришёл пример, и датасеты можно смешивать.

## Установка и подготовка данных

```bash
pip install -e ".[train,dev]"
bash scripts/prepare_clevrer_proactive.sh      # ~10 минут: вопросы и аннотации CLEVRER, генерация, балансировка, экспорт, тесты
VIDEOS=all bash scripts/prepare_clevrer_proactive.sh   # плюс 18,6 ГБ видео train + validation (нужны для обучения)
```

Корень данных — `./data`, его можно перенести переменной `DATA_ROOT`.

## Добавление нового датасета

1. `dataset_builders/<имя>/`: скачивание, построение, экспорт в `data/processed/<имя>/<split>.jsonl` через
   `online_vllm.data.schema`, свой `README.md` с описанием и статистиками.
2. `configs/data/<имя>.yaml` и `scripts/prepare_<имя>.sh`.
3. Тест инвариантов в `tests/`.
